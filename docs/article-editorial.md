# 記事内容と見た目の編集ルール

## Geminiが決める内容

記事構成は概要・変更内容・現場との関係・対応・当社の考察・次の行動という役割を保ち、固定の見出し文言を指定しません。各節の具体的な問いに合わせて `##` / `###` の見出しを生成します。事実と見解を分ける指示、公式の出典、最新情報取得、テーマの重複チェックは維持しています。

`buhio.comment` は20〜60文字。単なる励ましではなく、記事の要点や現場で取れる行動を親しみやすく伝えます。画像選択は引き続き6種類の固定画像から行います。

直近10件の公開記事から見出し・コメント・概要を取得します。同じ日の記事はGitの追加コミット順で並べるため、daily workflowは `fetch-depth: 0` で履歴を取得します。日付だけで並べて同日の古い10件を参照し続けることを防ぎます。

正規化後の一致・包含・2文字単位のDice類似度0.65以上を検査し、さらに独立したGeminiレビューで「意味がほぼ同じ問い・行動」「本文に根拠のないコメント」を検査します。問題があれば指摘と直前の案を渡して最大2回再生成します。直らない場合は `REPETITIVE_ARTICLE_STYLE` で停止し、下書き保存・公開しません。レビュー形式の不正も承認扱いにしません。意味の比較はモデルによる判定であり完全な保証ではありません。

## プログラムが整える見た目

GeminiはHTMLを書かず、本文の文字列と完全一致する `emphasis` を返します。選択結果はMarkdownのfront matterに保存します。

```yaml
emphasis:
  - text: 記録の置き場所
    style: strong
  - text: 担当者が変わっても情報が引き継がれるよう
    style: marker
  - text: 個人を特定できる情報を入力しない
    style: notice
```

- `strong`：短い重要語を `<strong>` に変換。最大30文字で段落丸ごとの指定は禁止。
- `marker`：`article-marker` のspan。落ち着いたオレンジ色の下線。
- `notice`：指定文を含む段落を `article-notice` の薄い背景の囲みにする。

各h2セクション最大2箇所、全体最大16箇所。同じ指定を繰り返し装飾しません。文字列の長さ・本文との一致・許可したstyleを検証し、HTML出力時はテキストをエスケープします。

Markdown変換は固定バージョンの `marked` を使用します。空行のない見出し、h1〜h6、太字・斜体・コード・リスト・表・引用を処理します。本文内h1はページタイトルと競合しないようh2へ変換。旧CMSの `==強調==` はマーカーへ変換します。日本語のかぎ括弧を太字にした直後に助詞が続く場合も専用トークンで処理します。既存の手書きHTML囲みは保持し、AI出力のHTMLは禁止のままです。

旧変換処理では、空行単位に分割したブロック全体が1行の見出しに一致する場合だけ処理していたため、`### 見出し` に本文が直結すると記号が露出していました。生成時と公開HTMLの書き込み前に露出を検査し、壊れたMarkdownを公開しません。コード例の中の記号は正当なコンテンツとして扱います。

## 下線アニメーションと読みやすさ

`assets/js/article-emphasis.js` は画面外のマーカーのみIntersectionObserverで監視し、画面内に入ると0.65秒で左から右へ下線を伸ばします。表示後は監視解除します。JavaScript無効・API非対応・動きを減らす設定では最初から下線を表示。記事本文はJavaScriptに依存せず表示します。h2はグリーンの左線と薄い背景、h3は小さめの文字と細い区切り線で区別します。

## 既存記事と検証

導入時に20件のMarkdown（公開18件・下書き2件）のコメントと強調指定を個別に更新し、固定見出しを記事に合う言葉に変更しました。本文の事実・出典URL・日付・公開状態を保持してHTMLを再生成しました。

`npm test` で変換、重複・類似判定、再生成上限、不正なレビュー、最新情報の取り込み、下書き保存、限定commit/push、公開制御、朝6時とcontinuous trialのワークフローを検証します。ブラウザでは320/375/1280px、下線の一度だけの動作、JavaScript無効、reduced motion、全公開ページの記号露出を確認しました。
