# ブログ自動投稿の引き継ぎ記録

作成日：2026-11-11（Claude が作成）。対象：福祉ITパートナーのブログ自動投稿の仕組み。
別のチャット（別のAI・別の担当）に作業を引き継ぐときに、最初に読むための記録です。

> 公開リポジトリのため、APIキーなどの秘密情報は書いていません。秘密の値は GitHub の
> Settings → Secrets and variables → Actions にだけあります。

## 0. 読む順番

1. このファイル（全体像・背景・注意点）
2. [docs/daily-blog.md](../daily-blog.md)（仕組みの詳しい仕様。変更の経緯が日付つきで残っています）
3. [docs/ai-shared/decision-log.md](decision-log.md)（確定した決定の記録）
4. 必要なときだけ：[docs/article-editorial.md](../article-editorial.md)（記事の見た目・強調のルール）、
   [docs/blog-publishing.md](../blog-publishing.md)（公開手順）

## 1. 一言でいうと

- 毎朝、GitHub Actions が AI（Google の **Gemini API**）で記事を1本作り、**自動で公開**します。
- 公開先は GitHub Pages の静的サイト（`https://fukushi-it-partner.com/`）。記事は `content/articles/*.md`、
  公開用の HTML は `blog/*.html` に入ります。WordPress などは使っていません。
- 自分のパソコンは動かす必要がありません（2026-10-06 から、すべてクラウドで動きます）。

## 2. 毎日の流れ

1. **05:00 頃（日本時間）** `YouTube Cache` が、動画の候補一覧（`data/youtube-cache.json`）を更新します。
2. **06:17 頃** `Daily Blog` が起動します。**09:17 頃**にも、取りこぼし対策のバックアップ起動があります。
   その日の記事がすでにあれば、何もせず終わります。
3. テスト（`npm test`）を実行し、通らなければ記事は作りません。
4. 動画候補（4チャンネル）からテーマを選び、既存記事と重複しないか確認します。
5. 記事本文を生成・検証し、下書き（`published: false`）として main に保存（commit・push）します。
6. 同じ記事だけを公開状態にして、HTML・一覧・サイトマップを更新し、GitHub Pages に公開します。
7. 失敗すると、GitHub に Issue（ラベル `daily-blog-failure`）ができて、メールで通知されます。

関連ワークフロー（`.github/workflows/`）：`daily-blog.yml`（記事作成）、`generate-blog.yml`（main への push の
たびに、サイト全体を作り直して公開）、`youtube-cache.yml`（動画候補の更新）、`generate-course.yml`（講座ページ）。

## 3. なぜ今の構造になっているのか（背景）

記録（コミット履歴と docs/daily-blog.md）から確認できる範囲です。理由が記録にないものは、そう書いています。

- **静的サイトで、GitHub が唯一の保管場所。** 記事もコードも履歴もすべてこのリポジトリにあります。
  AIが変わっても、GitHub を見れば状態が分かるようにするため、2026-10-24 に「AI間の共通情報は GitHub に置く」
  と決めました（decision-log 参照）。GitHub の文書は、ChatGPT などのメモリと自動では同期されません。
- **2026-09-11 に開始。** 最初は OpenAI で作り始め、同日に **Gemini API に切り替え**ました（切り替えの理由は
  記録に残っていません。現在 Gemini を使い続けている理由は、次の 3-2 を参照）。モデルは `gemini-3.5-flash-lite` が基本です（Repository Variable `GEMINI_MODEL`
  で `gemini-3.5-flash` にも変えられます）。
- **AIには「文章」だけを書かせる。** 日付・slug・ファイル名・画像・公開状態・出典は、コードが決めます。
  AIが作ったURLが記事に載ることはありません（出典は必ず候補一覧から解決）。間違いや事故を減らすための設計です。
- **下書き → 公開を、同じワークフロー内で行う。** GitHub の標準トークンでの push は、他のワークフローを
  起動しないため、Daily Blog 自身が公開まで続けて実行します。
- **公開は1本ずつ、直列で。** `Daily Blog` と `Generate Blog` は同じ `github-pages` の順番待ちグループを
  使います。待機できるのは1件だけで、新しい実行が入ると古い待機は置き換えられます。
- **テーマは YouTube 4チャンネルの動画だけ（2026-09-24〜）。** 精神保健福祉士うさぎ、益田裕介、WithYou、
  ケアきょう。毎回「発信者個人の見解を紹介する」形に統一するための方針です。公的機関のRSS取得コードは
  残してありますが、通常は使いません。動画が使えない日は、一般的な福祉ITのテーマ（evergreen）で書きます。
- **自宅PCは使わない（2026-10-06〜）。** 一時期、YouTube の取得が不安定で、自宅PCのランナーで動画候補を
  作っていました。クラウドで再び安定したため、やめました。古いランナー（`DESKTOP-RI19E2F`）は GitHub の
  Settings → Actions → Runners に残っていて、残っていても害はありません。不要なら削除できます。
- **バックアップ起動（2026-09-25〜）。** 2026-09-22〜24 に、06:17 の起動自体が記録に現れない日が続いたため
  です（原因は特定できていません）。
- **失敗への備えを、段階的に足してきた。** 失敗時の Issue 通知、記事内画像が足りないときの省略公開（10-14）、
  重複確認の16件ずつの分割（10-23）、「まとめ」見出しで止まらない対応（10-23）、AI出力の形が合わないときの
  その場での再試行、動画テーマの重複確認の省略（10-27）など。詳しい経緯は docs/daily-blog.md にあります。

## 3-2. なぜ今、Gemini を使っているのか（重要）

現在のこの仕組みは、**YouTube の動画をもとに記事を書く**ことが中心になっています。

- 4つのYouTubeチャンネルの動画から、その日のテーマを選び、**動画の内容そのもの**を踏まえて記事を書きます。
- Gemini API には、YouTube の公開動画のURLを渡すだけで、Google側のサーバーが**動画（音声・映像）の中身を直接
  理解してくれる公式の機能**があります（`scripts/topic-selector.js` の `fileParts`、詳細は docs/daily-blog.md の
  「記事生成時はGeminiに動画そのものを直接理解させる」）。2026-09-19 に、実際のAPIで動作を確認して導入しました。
- 一方、**Claude は、この仕組みの中では動画の中身を見られません**（動画のURLだけでは、内容が分かりません。
  取得できるのは動画のタイトルと概要欄だけです）。そのため、動画をもとに記事を書く部分は、Gemini に頼っています。
- したがって、**Gemini をやめて Claude などに全面的に切り替えると、動画をもとにした記事は書けなくなり、
  動画に関係しない一般テーマ（evergreen）の記事だけになります。** 方針を決めるときの大きな判断材料です。

> 経緯の正確さについて：2026-09-11 に OpenAI から Gemini へ切り替えた時点では、まだ YouTube 動画は使っていません
> （動画を使い始めたのは 2026-09-18 以降）。つまり、**最初に Gemini を選んだ理由は記録に残っていません。**
> ただし、その後に動画対応を Gemini の機能で作ったため、今は「動画を理解できること」が Gemini を使い続ける
> 主な理由になっています（所有者の認識も同じです）。

## 3-4. Claude と Gemini の役割の違い（方針を決めるときの整理）

| | Gemini（今の自動投稿） | Claude（手作業・定期タスク） |
|---|---|---|
| 動画の中身を理解して書く | できる（公式の機能） | この仕組みでは**できない** |
| 動画に関係しない一般テーマの記事 | 書ける | 書ける |
| 動く場所 | GitHub のクラウド（パソコン不要） | **このパソコン上**（定期タスクは、パソコンとアプリが動いている必要がある） |
| 費用 | Gemini の前払い残高（切れると止まる） | Claude の利用枠 |
| 公開の安全装置（テスト・画像ルール） | 同じ仕組みを通る | 同じテストを通す必要がある |

## 4. 重要なルール（壊しやすいところ）

- **自動投稿の実行中は、main に push しない。** 下書き保存・公開の途中で main が動くと、安全装置が働いて
  失敗します（`DRAFT_MAIN_CHANGED`）。force push・merge・rebase は、仕組みとして行いません。
- **テストが通らないと、毎朝の記事も作られない。** `npm test`（現在285件）が入口で動きます。記事や画像を
  手で足したときも、必ず `npm test` を通してから push してください。
- **画像のルール（テストで守られている）。** 一覧で隣り合う記事が、同じ系統・同じ場面のヒーロー画像に
  ならないこと／ヒーロー画像は直近20本で重複しないこと／記事内画像は直近10本で重複しないこと。
  過去の日付の記事を足すときは、その日付の前後の記事を基準に画像を選びます（`asOfDate`）。
- **記事のルール。** 本文は1,200〜3,500字（H2は3つ以上）。URL・リンク・HTML・画像は本文に入れない。
  「まとめ」などの固定見出しは使わない（`scripts/lib/editorial.js` の `FIXED_HEADINGS`）。強調（strong は30字以内）は
  1つの見出しにつき2つまで。ぶひお（キャラクター）のコメントは20〜60字。
  カテゴリは決まった一覧からだけ選べます。
- **出典の日付とのつじつま。** 出典（動画・公的機関）のある記事は、出典より前の日付にしないこと。
  出典の日付が分からないときは、作成日より後にする。
- **料金・サービス内容は、このリポジトリの文書が正式。** 古い会話やメモだけで上書きしない。
  顧客情報・認証情報は書かない（リポジトリは公開）。
- **WindowsのCRLF。** 多くのファイルが CRLF（改行コード）です。スクリプトで書き換えるときは、改行を
  保ったまま編集してください。
- **作業前に確認：** `git remote -v` が `https://github.com/uk-support1/fukushi-it-partner-site.git` であること。
  `yasuragi-no-kai-site`（別プロジェクト）は絶対に触らない。詳しくは [CLAUDE.md](../../CLAUDE.md)。

## 5. 手動操作

- **今日の記事を作り直す／追加で作る：** Actions → Daily Blog → Run workflow（手動実行は「その日すでに記事が
  ある」判定の対象外）。
- **過去の日付の記事を作る（穴埋め）：** Run workflow で `target_date`（今日より前の `YYYY-MM-DD`）と
  `evergreen_only: true`。出典なしの一般テーマで、その日付の記事ができます。続けて何本も作るときは、
  前の実行が終わってから次を実行します。
- **失敗通知の確認：** `simulate_failure: true` で、意図的に失敗させて Issue 通知を試せます。
- **YouTube側だけ切り分け：** `sources_filter`（`auto`／`cache`／`live`）。
- **ローカル確認：** `npm test`、`node scripts/generate-blog.js`。実際のAIを呼ぶと費用が発生します。
- **記事を手で書いて足す方法（AIに頼めない日の代替）：** `scripts/article-writer.js` の `saveArticleDraft` で
  記事ファイルと画像選定をコード側に任せ、`published: true` にしてから `node scripts/generate-blog.js`、
  `npm test`、push の順です。2026-11-08 に、この方法で記事17本（漏えい記事5本＋穴埋め12本）を追加しました。

## 6. よくある失敗と対処

| 症状（Actions のログ） | 意味・対処 |
|---|---|
| `GEMINI_HTTP_ERROR`（402 / RESOURCE_EXHAUSTED、「prepayment credits are depleted」） | Gemini の**前払い残高が尽きた**。時間では回復しない。Google AI Studio（https://ai.studio/projects）で課金・残高を確認し、チャージする（これは所有者本人の操作）。 |
| `GEMINI_HTTP_ERROR`（429） | 1分あたり等の回数・トークン制限。時間がたてば回復。動画の添付は1回目の生成だけに絞ってある。 |
| `DUPLICATE_TOPIC` | 既存記事と同じテーマ。自動で別テーマを最大5回選び直す。それでも駄目なら失敗。 |
| `INCOMPLETE_DUPLICATE_REVIEW` / `ARTICLE_LOCAL_STYLE_RETRY_EXHAUSTED` | AIの応答の不備・文体チェック違反。自動で再試行し、尽きたら失敗（Issue ができる）。 |
| `DRAFT_MAIN_CHANGED` | 実行中に main が更新された。時間をおいて再実行。 |
| 06:17 の実行が記録にない | GitHub 側の取りこぼし。09:17 のバックアップ起動が拾う。 |
| テスト失敗で記事が作られない | 手動で足した記事や画像がルール違反になっていることが多い（画像の隣接重複など）。 |
