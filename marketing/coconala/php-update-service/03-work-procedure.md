# 03 作業手順（更新前バックアップ・互換性の確認・更新後の動作確認）

2026年10月23日。**ココナラへの出品操作は、まだ行っていません。** この手順は、実際の作業の標準です。お客様の情報（URL・認証情報・バックアップの中身）は、**このリポジトリに保存しない**でください（保存先はリポジトリの外）。作業ごとのチェックシートは `templates/work-checklist.md`、報告書は `templates/work-report-template.md`、チャットの定型文は `templates/chat-messages.md` です。

> **検証の状況：** この手順のうち、バックアップ・中身の確認・復元・切り替え・切り戻しは、**実際にWordPressを動かして検証済み**（コンテナ内。失敗0件。`11-verification-report.md`）。**サーバー会社の管理画面・バックアップ機能での検証は未実施**（`verification/hosting-test-checklist.md`）。**受注は、その検証が済んでから**。

## 0. 基本の考え方（5つ）

1. **まず見るだけ。変更するのは、最後の「PHPの切り替え」だけ。** 手順の前半は、すべて「見る」「取る」作業。サイトを変える作業は、PHPの切り替え（と、事前に了承を得た必要最小限の更新）に限る。
2. **元に戻せる状態で進める。** 切り替えの前に、「元の版」を記録し、バックアップを取り、**戻し方を確認**してから切り替える。戻せないときは、切り替えない。
3. **PHPだけ上げる。** プラグイン・テーマは、更新先のPHPで動かすために**どうしても必要なとき以外は、更新しない**。PHPだけの変更なら、不具合が出ても「版を選び直す」だけで元に戻せる（プラグインの更新は、データベースを書き換えることがあり、PHPを戻すだけでは戻らない）。
4. **150分を超えそうなら、元に戻して止める。** 赤字案件・長期化を防ぐ。選択肢を報告して、お客様に決めていただく。
5. **お客様に分かる言葉で、書面を残す。** 何をしたか・何を確認したか・どう戻すかを、作業完了報告書で渡す。

## 4. P2 バックアップ

### 4-1. 方法（優先順位）

| 優先 | 方法 | 注意 |
| --- | --- | --- |
| 1 | **サーバー会社のバックアップ機能**（自動バックアップ、ワンクリックバックアップ、スナップショット） | 取得日時を確認する。**復元の方法**を、公式マニュアルで確認しておく |
| 2 | サーバー管理画面のファイルマネージャー＋データベースの書き出し（phpMyAdminなど）で、**ファイルとデータベース**を取得 | 保管先は、**お客様のサーバーの公開されていない場所**（ドキュメントルートの外）か、サーバー会社の機能の中 |
| 3 | WordPressのバックアップ用プラグイン（導入する場合は、**お客様の了承を得て**。作業後に削除し、報告書に書く） | プラグインの導入は、サイトの変更になる。バックアップファイルが公開領域に残らないようにする |

### 4-2. 確認（取っただけで終わりにしない）

| # | 確認 |
| --- | --- |
| 1 | 取得日時が**作業の直前**である（古いバックアップと取り違えない。**作業ごとに、日付つきの別の保管場所**を使う） |
| 2 | ファイルの容量・**ファイルの数**が、サイトと同程度（極端に少なくない）。zipなどの圧縮ファイルが**開ける**（壊れていない） |
| 3 | データベースの書き出しが、**中身を開いて**、投稿・固定ページ・設定のデータが入っている（途中で切れていない） |
| 4 | 保管場所が、**公開されていない場所**で、外から開けない（**公開フォルダに置くと、URLを知られれば取得できてしまう**。実機検証で確認） |
| 5 | **復元の方法**を、手順として確認した（サーバー会社の復元機能、または手作業の手順） |
| 6 | （できる場合）**別の場所へ復元して、元と同じ表示になること**を確認する。バックアップの完全性の確認になり、**テスト環境（オプション）の代わり**にもなる（`11-verification-report.md` S2-4） |

### 4-3. バックアップの扱い（個人情報）

- 福祉事業所のサイトには、**お問い合わせの内容や、利用者・職員の個人情報**が含まれることがある。バックアップは、**作業者の端末にダウンロードしない**。お客様のサーバー内、またはサーバー会社の機能の中に保管する。
- 保管したバックアップの**場所と名前**を、作業完了報告書に書く。**残すか削除するか**は、お客様にうかがう（既定：7日後に削除してよいか、確認する）。
- お客様ご自身で保存したい場合は、サーバー管理画面からのダウンロードの方法を案内する（バックアップのお渡しのオプションは設けない。`02-pricing-and-scope.md` §3）。

## 5. P3 互換性の確認

### 5-1. 確認の方法

| # | 方法 | 内容 |
| --- | --- | --- |
| 1 | **対応PHPの確認** | テーマ・各プラグインの「必要なPHPの版」「動作確認済みの版」「最終更新日」を、配布元（WordPress.org のプラグインページ、テーマ提供元）で確認 |
| 1b | **公式の「必要なPHPの版」を、プラグインごとに調べる**（読み取りだけ） | WordPress.org のプラグイン情報（`requires_php`）。**最新版が新しいPHPを要求している場合は、PHPを上げないと、そのプラグインを最新版にできない**（例：Contact Form 7 の最新版は8.3以上。8.1のままでは、WordPressが更新を断る）。PHPを上げたあとの、互換性のための更新の判断材料になる |
| 2 | **エラーログの確認** | 現在のエラーログに、**非推奨（Deprecated）**や**警告**が出ていないか。更新先のPHPで問題になる記述のヒントになる |
| 3 | **PHPの互換性チェック用プラグイン** | WordPress公式のPHP更新ガイドが紹介している方法（導入は、お客様の了承を得て。作業後に削除）。使わなくても確認できる範囲で進める |
| 4 | **テスト環境での検証**（オプション2） | サイトの複製をサーバーの機能で作り、更新先のPHPで動くかを**先に**見る。作れないサーバーでは行わない |
| 5 | 独自のプログラム・古いプラグイン | **PHP 8 で削除された関数の検索**（`create_function`・`each()`・`money_format`・`mysql_*` など。**`*.php` のみ**を対象にする。JavaScript の `.each(` を拾わない）。**構文チェック（`php -l`）だけでは、これらは見つからない**（構文エラー0件でも、PHP 8.3 で表示されなくなった。`11-verification-report.md` S2-3・S2-6）。構文チェック・検索は、SSHなどが使える環境のみ。使えない場合は、目視で確認できる範囲と、テスト環境（オプション2）で補う。コードの修正は、別途見積り |

### 5-2. 判定（3段階）

| 判定 | 意味 | 次の進め方 |
| --- | --- | --- |
| ○ 問題なし | 対応PHPの版に含まれ、最近まで更新されている | そのまま進める |
| △ 要注意 | 更新が数年止まっている／対応版の記載がない／エラーログに警告がある | 影響が出る機能を明らかにし、お客様の了承を得て進める。**切り戻しの準備**を念入りに |
| × 対応していない | 配布元が「このPHPの版は未対応」と書いている／閉鎖された／エラーが出ることが分かっている | **更新しない**。代わりの選択肢を報告（`05-failure-policy.md` §3） |

### 5-3. 互換性のための更新（基本プランは3つまで）

- 更新ファイルが公開されている、テーマ・プラグインを更新すれば動く場合のみ。**1つずつ**、お客様の了承を得て更新する。
- 更新の前に、バックアップが最新であることを確認する。**更新した内容（名前・前後の版）**を記録し、報告書に書く。
- プラグインの更新は、データベースを書き換えることがある。**PHPを戻しても戻らない**ため、記録を残す。3つを超える場合は、オプション4または別途見積り。
- **「最新版が新しいPHPを要求する」プラグインは、PHPを先に上げてから更新する**（上げる前は、更新自体が断られる）。PHPだけを先に更新し、動作確認のあとに、必要なプラグインを更新する順番が、切り戻しやすい。

## 6. P4 PHPの切り替え

| # | 作業 | 備考 |
| --- | --- | --- |
| 1 | お客様に「これから切り替えます」と連絡 | アクセスが少ない時間帯。フォーム・予約などを使っている場合は、その旨を伝える |
| 2 | **現在の設定画面の写真**（元の版が分かるもの）を保存 | 戻すときの根拠になる |
| 3 | 目標の版を選ぶ：**標準は8.3系**。ご希望・プラグインの対応状況により8.4系以降も可 | 8.3系は、2027年12月31日までセキュリティサポートが続く（PHP公式） |
| 4 | **切り替えを実行** | サーバー会社ごとの手順は `04-server-compat-and-credentials.md` §1。ドメイン単位の設定のため、**対象のドメインだけ**を変更する |
| 5 | **反映を待つ** | ロリポップ！は5〜10分（公式ヘルプの要約）。そのほかは、画面の案内に従う |
| 6 | **実際の版を確認**（サイトヘルス） | 選んだ系列になっているか。**番号が、今回の修正版以上か**を比較（8.3系なら8.3.36以上） |

**番号が修正版より前に見える場合：** サーバー会社が、番号を変えずに修正している場合がある。**更新が失敗した、とは言わない。** サーバー会社の公式のお知らせ（対応済みの案内）と照らして、報告書に「サーバー会社が対応済みと案内。番号は変わらないことがある」または「確認先」を書く（確認商品の判定のきまりと同じ。`../06-scope-and-fallback.md` §5）。

| # | 項目 | 方法 |
| --- | --- | --- |
| 1 | 版の表示 | サイトヘルス「情報 → サーバー」 |
| 2 | トップページ・主なページ（5〜10ページ）の表示 | 画像・レイアウト・文字化け。**P1で記録した更新前の表示と、見比べる** |
| 3 | スマホの表示 | 幅の狭い画面で |
| 4 | 投稿一覧・固定ページ・検索・ページ送り | |
| 5 | **管理画面**へのログイン・ダッシュボード・投稿の編集画面 | 保存はしない（開くだけ） |
| 6 | **お問い合わせフォーム**の送信テスト | **お客様の了承を得て**、お客様宛ての送信であることを確認し、「テスト」と明記。メールの受信まで確認 |
| 7 | 画像・メディアの表示（ライブラリ） | |
| 8 | **止まると困る機能**（予約・会員ページ・決済など）の入口 | ヒアリングで挙がったもの。**決済・個人情報の入力は行わない**。お客様側での最終確認をお願いする |
| 9 | **エラーログ** | 更新前より**増えていない**か。新しいエラー・警告があれば記録 |
| 10 | サイトヘルスの表示 | PHPに関する「要対応」が消えているか |
| 11 | WordPressの自動実行（スケジュールされた投稿など）、メール送信 | 確認できる範囲で |

### 7-2. 結果の判定

| 結果 | 次 |
| --- | --- |
| すべて問題なし | P7（報告）へ |
| **軽微な警告のみ**（表示に影響しない） | お客様に報告し、そのまま進める（記録） |
| **表示・管理画面・主な機能に問題** | **直ちに切り戻し**（P6） |
| 判断がつかない | 切り戻して、原因を整理（P6） |

## 8. P6 切り戻し（不具合が出たとき）

| # | 作業 |
| --- | --- |
| 1 | **まず、サイトを見える状態に戻す**：サーバー管理画面で、記録した**元のPHPの版**を選び直す。反映を待つ |
| 2 | 戻した後の表示確認（トップ・管理画面・主な機能）。**元の状態と同じ**であることを確認 |
| 3 | 原因の切り分け：エラーログの**ファイル名・パス**から、どのプラグイン・テーマが原因かを特定（コードの修正はしない） |
| 4 | お客様にチャットで報告：何が起きたか／元に戻したこと／原因とみられるもの／選択肢（`05-failure-policy.md` §3）／費用 |
| 5 | 選択肢をお客様が選ぶまで、**元の版のまま**にしておく |

**バックアップから復元するのは最後の手段**（PHPの版を戻しても直らない場合のみ）。復元は、データを書き換える作業のため、お客様に連絡し、了承を得てから行う。

## 9. 中断（150分を超えそうなとき・中断する条件）

次のときは、**切り替えを中止して元の状態に戻し**、報告する。

| 条件 | 対応 |
| --- | --- |
| 作業が150分を超える見込み | 中断。選択肢（オプションの追加・別途見積り・見送り）を報告 |
| 元に戻せないことが分かった | 切り替えない。報告 |
| サイトの表示・管理画面が、3分以上戻らない | 切り戻し。それでも戻らなければ、復元の了承を得る |
| 不審なファイル・設定（改ざんの痕跡の可能性）を見つけた | **作業を止める。** 調査・除去は行っていない旨と、サーバー会社・専門業者への相談を案内（確認商品と同じ方針） |
| お客様から返信がない | `05-failure-policy.md` §6 |
