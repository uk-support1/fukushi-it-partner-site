### 1-2. 受付の方針

1. **標準で受けるのは、公式マニュアルで切り替えと切り戻しの手順を確認できた会社だけ**（現時点：さくら、ConoHa WING。エックスサーバーは**切り替え手順は確認、戻す手順は未確認**。ロリポップ！は**条件つき**）。そのほかは、購入前にご相談いただく。
2. **実績が積み上がるまで、受付を絞る。** 作業のたびに、公式マニュアルの最新の画面を確認する。
3. **ご本人（作業者）が、実際に作業の経験があるサーバー会社を選ぶ。** 出品文に会社名を載せる範囲は、経験のある会社に限る（出品文の該当箇所は【要確認】）。
4. **「元に戻せるか」の確認**を、受付の最初に行う（`03-work-procedure.md` P1の#4）。元の版が選択肢にないサーバーは、受けない。
5. ドメインごとの設定のサーバー（エックスサーバー・ConoHa WINGなど）では、**対象ドメインだけ**を切り替える。ほかのドメインのサイトに影響しないことを確認する。
6. **サーバー会社が自社で修正済みの場合の説明：** PHPの版を切り替えなくても、**今回の件では緊急の作業が要らない**場合がある。そのことを正直に伝える。**ただし、8.1以前（公式の更新が出ない）や、8.2系（2026年12月31日で終了）は、サポート中の版への移行に意味がある**（`02-pricing-and-scope.md` §0）。

## 2. 必要な権限（最小限にする）

| 権限 | 使う場面 | 必須か | 渡し方 |
| --- | --- | --- | --- |
| **WordPressの管理者権限** | サイトヘルス、プラグイン・テーマの一覧、動作確認（管理画面） | 必須 | **臨時の管理者ユーザー**（作業後に削除） |
| **サーバー管理画面** | PHPの切り替え、サーバーのバックアップ機能、エラーログの確認 | 必須（ただし下の代替あり） | **お客様が臨時の権限を作れる会社は、その権限**（できる会社かは❓。**多くの会社で、ログイン情報の共有が必要になる**）。**代替：お客様が切り替えのボタンだけ押す**（当方は、画面の写真で、チャットで案内） |
| **FTP／SFTP** | ファイルマネージャーが使えない場合の、ファイルのバックアップ | 必要な場合のみ | **臨時のFTPアカウント**（作業後に削除） |
| データベース（phpMyAdminなど） | 管理画面の機能がない場合のデータベースの書き出し | 必要な場合のみ | サーバー管理画面からの利用（別のIDは通常不要） |
| ドメイン・DNS・メール・お支払い | — | **不要（求めない）** | — |
| 決済・会員の個人情報 | — | **閲覧しない** | 動作確認は、入口までにする |

### 2-1. 「お客様が切り替えボタンだけ押す」代替（権限を最小にする方法）

| 手順 | 内容 |
| --- | --- |
| 1 | WordPressの臨時管理者ユーザーだけをお渡しいただく（サーバー管理画面は渡さない） |
| 2 | バックアップは、**サーバー会社の機能**（お客様が実行）、またはWordPressのバックアップ用プラグイン（当方が、了承を得て導入）で取得 |
| 3 | PHPの切り替えは、**お客様が、チャットの案内に沿って実行**（当方は、画面の写真の案内を用意） |
| 4 | 切り替え後の確認は、当方（WordPress管理画面とサイトの表示） |

**長所：** サーバーの強い権限を渡さずに済む。**短所：** お客様の手間が増え、IT初心者には難しい。標準は「臨時アカウントをお渡しいただく」にし、希望があればこの代替を使う。

## 3. 認証情報の安全な扱い（ルール）

| # | ルール |
| --- | --- |
| 1 | **やりとりは、ココナラのトークルームの中だけ。** メール・LINE・外部のフォーム・SNS・**添付ファイル**は使わない。（ココナラは、外部へ誘導する行為や連絡先の交換を禁止している。競合の出品でも、添付ファイルでの受け渡しは避けるよう求めている）**【要確認】トークルーム内でID・パスワードを受け渡すことの可否は、ココナラの規約・ヘルプで未確認。競合は実施している。出品画面・サポートで確認する** |
| 2 | **臨時のアカウントを作っていただく。** お客様ご自身の普段のアカウントは、お預かりしない。WordPressは「ユーザー → 新規追加 → 権限グループ：管理者」で作成（手順を案内） |
| 3 | **二段階認証は解除していただかない。** 作業の時間にチャットで待機し、その場で確認コードをお知らせいただく |
| 4 | **作業用のブラウザーを使う。** パスワードの保存・自動入力はオフ。作業端末に、認証情報のメモやファイルを残さない |
| 5 | **画面の写真・報告書に、認証情報や個人情報を写さない。** 撮ったら見直す |
| 6 | **範囲外を見ない。** 動作確認に必要な範囲だけを開く。問い合わせの内容・会員の情報・利用者の情報は、読まない |
| 7 | **取得したバックアップは、持ち出さない。** お客様のサーバー内、またはサーバー会社の機能の中に保管する（`03-work-procedure.md` §4-3） |
| 8 | **導入したものは、元に戻す。** 作業のためにインストールしたプラグインなどは、作業後に削除し、報告書に書く |
| 9 | **作業後に、お客様にお願いする：** ①臨時のWordPressユーザーを削除 ②サーバー管理画面のパスワードを変更（お渡しした場合） ③臨時のFTPアカウントを削除 ④解除していた設定を元に戻す。当方は、保存した情報を消去したことを報告 |
| 10 | **お願いしないもの：** ドメインの管理者権限、お支払いの情報、メールアカウントのパスワード、お客様のココナラのログイン情報（規約で、アカウントの共有は禁止） |
| 11 | **誤って送ってしまった・漏れたかもしれない場合：** すぐにお知らせいただき、パスワードを変更していただく。当方は、記録を消去して報告 |
