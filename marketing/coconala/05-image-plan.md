### この順番にした理由

1. **1〜3枚目が、最初に目に入る**（一覧では1枚目、詳細ページでは続けて2・3枚目が見える、というのが目安）。「訴求 → 状況 → 何がもらえるか」の順にして、**3枚目で、実物の報告書を見せます**。抽象的な説明より、実物のほうが、「2,000円で何が得られるか」が伝わるためです。
2. **見本を2枚続けて並べる**（△と◎）。結果が2通りあること、「更新しなさい」と言われるだけではないことが伝わり、売り込まない姿勢にもなります。
3. **4段階の説明（5枚目）は、見本のあとに置く。** 見本で実物を見たあとに、種類を整理すると、理解しやすいためです。
4. **料金（6枚目）は、価値が伝わったあとに置く。** 価格は1枚目にも出ているため、料金表を後ろに置いても、価格が分からない状態にはなりません。
5. **流れ（7枚目）と範囲（8枚目）は、購入の不安を取り除く最後の押し。** 特に、「ログイン情報は不要」「見つからなくても大丈夫」「できないことも先に伝える」は、信頼につながります。
6. **9枚目（売り込みません）は予備。** 4・6枚目の「必要な方だけ」と、説明文の「無理におすすめはしません」で、同じことは伝わっているため、外しました。10枚の枠に余裕があるので、「信頼」を強めたい場合は、最後に足せます。

> 枚数を減らす場合の優先順位：**1・2・3・6・8**（訴求／状況／実物／料金／範囲）を残し、4・5・7を外す。逆に、枚数を増やすなら、9を最後に足す。

## 6. 書き出し方と、直す場所

```sh
# リポジトリのルートで（playwright と Chromium が必要。フォントは Google Fonts から読み込むのでネットワークが必要）
node marketing/coconala/images/src/build.js            # 3〜9枚目（プランA）→ images/（※1・2枚目はChatGPT版のため、書き出しません）
node marketing/coconala/images/src/build.js --plan-b   # 06-plans（プランB）→ images/plan-b/
node marketing/coconala/images/src/build.js 05         # 番号を指定して、1枚だけ
```

| 変わること | 直す場所 |
| --- | --- |
| 色・フォント・ラベル・余白 | `images/src/common.css` |
| アイコンの形 | `images/src/icons.js` |
